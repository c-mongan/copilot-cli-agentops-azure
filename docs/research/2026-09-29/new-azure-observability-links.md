# September 2026 Azure observability links: product impact

The four links supplied by the user are research inputs, not instructions or proof that this project is production ready. Prefer the Microsoft documentation for feature and support claims. The Medium article is a useful implementation example, not a product contract.

| Source | What it adds | Decision for this repository |
| --- | --- | --- |
| [Azure Monitor Observability Agent](https://learn.microsoft.com/en-us/azure/azure-monitor/aiops/observability-agent-overview) | A natural-language helper that investigates Azure Monitor data and incidents; autonomous operation has a separate preview resource. | Optional investigation layer after telemetry exists. It is not the collection pipeline or a Copilot CLI run recorder. Do not provision it for the first slice. |
| [Monitoring Copilot agents with OTel and Grafana](https://medium.com/@tajinder.singh1985/monitoring-github-copilot-agents-with-opentelemetry-and-grafana-f1a46d50d5ac) | Illustrates OTel export and Grafana trace inspection. | Use as a visual example only. Verify settings and data contracts against [Microsoft's coding-agent setup](https://learn.microsoft.com/en-us/azure/managed-grafana/grafana-opentelemetry-app-insights) and [GitHub's Copilot CLI telemetry reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference). Keep this repo's Collector route. |
| [Foundry Agent Monitoring Dashboard](https://learn.microsoft.com/en-us/azure/foundry/observability/how-to/how-to-monitor-agents-dashboard?view=foundry) | Operational metrics and continuous evaluation for agents associated with a Foundry project and Application Insights. Some features are preview. Custom agents require onboarding and matching OTel GenAI conventions. | Reuse for future Foundry-backed agents; do not add a Foundry project solely to display local Copilot CLI runs. |
| [Application Insights Agents view](https://learn.microsoft.com/en-us/azure/azure-monitor/app/agents-view) | Native agent run/error entry points, a simple end-to-end transaction view, content search when enabled, and a Grafana exploration path. It explicitly includes coding agents. | Make this the default fleet/operations view when native OTel traces arrive. Test the trace story with synthetic Copilot CLI data before claiming complete coverage. |

Microsoft also provides [prebuilt coding-agent Grafana dashboards](https://learn.microsoft.com/en-us/azure/managed-grafana/grafana-opentelemetry-app-insights) for GitHub Copilot and Codex, accessible in Azure Monitor without a separate Grafana instance. They cover aggregate operations, tokens, sessions, tools, latency, and errors. This substantially reduces the need to build custom overview charts. The initial product should put one failed session's timeline, prompt, tool arguments/results, source evidence, and replay/export controls behind the operational overview. The current local session waterfall is a first implementation of that detail view; its OTel correlation and Azure content readback still need proof.

The native guidance shows content capture as an explicit setting and notes privacy policy implications. For this personal EVAL environment, use synthetic content with explicit capture. Enterprise onboarding needs per-environment capture policy, retention, role-based access, and evidence that disabled capture stops future exports. Redaction later does not remove content already ingested.
